## 前提与边界

- 当前目录 `D:\code\pi-desktop-plugins\model-usage-dashboard` 完全为空，且不是 Git 仓库；尚无 PI-Desktop SDK、插件模板或设计规范可供对齐。
- 实现目标为 **PI-Desktop 原生插件**。开始编码时先导入用户提供的官方 SDK/示例模板，并以其真实 manifest、生命周期、权限、主题组件和本地存储接口为准；下述文件名可按 SDK 约定微调，但模块边界保持不变。
- 首版支持：OpenAI API、Anthropic API、Google Gemini API、OpenRouter、兼容 New API/Sub2API 的第三方中转（包括“帅 API”），以及 PI-Desktop 已接入的 ChatGPT/Claude 官方订阅渠道。
- 不抓取网页、不调用逆向或私有接口、不伪造额度。官方订阅若无公开用量/计费 API，只展示 PI-Desktop 本地请求事件或服务端响应头中能验证的数据；不支持的费用、额度、重置时间字段直接隐藏，并解释缺失原因。

## 实现方案

### 1. 初始化原生插件骨架并对齐设计系统

- 基于 PI-Desktop 官方示例建立 `package.json`、插件 manifest、TypeScript/React 构建配置、入口文件及开发/打包脚本。
- 使用 PI-Desktop 的主题 token、字体、间距、卡片、表格、Tooltip、空状态、错误状态和深浅色模式；不自建冲突的视觉体系。
- manifest 仅申请必要权限：读取宿主提供的渠道元数据/用量事件、访问用户明确启用的渠道 API、插件私有本地存储；不申请任意文件系统或无关网络权限。

### 2. 建立可扩展的统一领域模型

在 `src/core/` 定义并贯穿采集、存储与 UI：

- `Channel`：渠道 ID、类型、显示名、API 基址、账号/组织标识的脱敏值、启用状态。
- `UsageSample`：请求数、输入/输出/缓存 Token、费用、币种、额度使用/上限、窗口起止与重置时间。
- `MetricValue`：值、单位、采集时间、来源类型（官方 API / 响应元数据 / PI 本地事件 / 官方价格推算）、来源说明、是否估算。
- `Capability`：每个渠道逐项声明 requests/tokens/cost/quota/reset/history 能否提供，UI 据此隐藏字段而非补零。
- `ProviderAdapter`：`discoverCapabilities`、`collectSnapshot`、`normalizeEvent`、`healthCheck` 接口，后续增加渠道不改动主流程。

### 3. 渠道发现与采集适配器

在 `src/adapters/` 实现：

- **PI-Desktop 宿主适配器**：通过 SDK 枚举已接入渠道并订阅本地请求完成事件；只保存统计所需字段，不保存 prompt、回复正文或完整密钥。官方 ChatGPT/Claude 订阅主要使用该来源。
- **OpenAI API**：优先使用官方组织 Usage/Costs 接口（仅在现有凭据具备相应权限时）；普通调用则从本地请求事件/官方响应 usage 汇总 Token。
- **Anthropic API**：优先使用官方 Usage/Cost 管理接口；普通调用从响应 usage 汇总输入、输出及缓存 Token。
- **Google Gemini API**：从官方响应 `usageMetadata` 采集 Token；只有存在官方账单数据接口且凭据有权访问时才展示真实费用/额度。
- **OpenRouter**：使用其公开余额/用量能力与响应中的 usage；能力探测失败时退回本地事件。
- **New API/Sub2API/OpenAI-compatible**：提供声明式端点配置和安全的只读能力探测，兼容常见 usage/quota/billing 响应，但必须保留原始来源说明；为“帅 API”建立配置实例，不硬编码特定站点秘密或未经确认的接口。
- **ChatGPT/Claude 官方订阅**：显示渠道及本地可验证请求趋势；仅当宿主 SDK 或官方响应明确提供窗口额度/重置时间时展示这些字段，不访问账号网页或私有会话接口。
- 所有适配器均设置超时、取消、指数退避与可理解错误；单一渠道失败不影响其他渠道。

### 4. 本地隐私存储与聚合

- 在 `src/storage/` 使用 SDK 提供的插件私有数据库；若 SDK 无数据库能力，则使用插件沙箱内 SQLite（具体实现随 SDK 确认）。
- 保存渠道脱敏信息、分钟/小时/日聚合、最近采集状态和来源元数据；默认不保存请求内容、响应内容、完整 URL 查询参数或密钥。
- 凭据只通过 PI-Desktop 安全凭据句柄调用；确需新增管理级只读密钥时存入系统 Keychain/宿主 Secret API，不进入数据库、日志或前端状态持久化。
- 聚合保留策略默认：细粒度 30 天、日聚合 1 年，可由用户清除；提供“一键删除全部本地用量数据”。
- 费用只接受官方账单值，或依据带版本日期和来源链接的官方价目表计算并醒目标记“估算”；绝不把估算值伪装成账单。

### 5. 仪表盘与交互

在 `src/ui/` 实现：

- 顶部总览：请求数、Token、费用、已知额度使用率；仅汇总单位/币种和语义兼容的数据，避免错误相加。
- 渠道卡片/表格：按渠道展示支持的请求数、Token、费用、额度、重置倒计时、最后同步时间和健康状态；缺失指标不占位或显示“数据源不提供”。
- 历史趋势：7/30/90 天范围，请求、Token、费用可切换，支持总览与单渠道对比；时区明确使用本地时区显示、UTC 存储。
- 数据来源抽屉：逐指标展示来源、采集时间、估算状态、权限要求和不可用原因，让数据可核验。
- 渠道设置：启停采集、检测连接、配置兼容 API 能力端点、数据保留与清除；敏感值永不回显。
- 完整覆盖加载、无渠道、无历史、部分失败、离线、权限不足和窄窗口状态，并满足键盘操作、对比度及减少动画设置。

### 6. 采集调度与可靠性

- 宿主事件实时增量写入；官方统计/余额 API 使用低频定时同步与手动刷新，避免重复计数和触发限流。
- 以渠道、时间桶、服务端事件 ID（若有）建立幂等键；明确区分本地观测值与服务端账单值，避免二者叠加。
- 记录结构化但脱敏的诊断信息；UI 可查看适配器状态与最近错误，不包含凭据或请求正文。
- 离线时继续展示本地历史并标记陈旧时间，恢复联网后补采官方允许回溯的时间段。

## 验证与验收

- **单元测试**：各渠道响应标准化、缺字段处理、Token 分类、费用精度、时区/重置窗口、聚合、幂等去重、脱敏。
- **契约测试**：使用脱敏 fixture 覆盖官方 API 和 New API/Sub2API 常见变体；未知字段与接口错误不会导致全局失败。
- **隐私测试**：扫描数据库、日志和前端持久状态，确认无 API key、prompt、回复正文；删除操作后无残留统计记录。
- **UI 测试**：能力字段显隐、来源抽屉、部分失败、离线、空状态、深浅色、键盘导航与窄窗口布局。
- **端到端验证**：在 PI-Desktop 开发宿主中安装插件，连接至少一个官方 API、一个兼容中转和一个官方订阅渠道，发起可控请求后核对本地事件、官方 usage/账单值与趋势图；确认无公开数据时费用/额度/重置时间确实不显示。
- **构建验收**：运行 SDK 要求的 lint、typecheck、test、build/package，并通过 PI-Desktop 插件校验器；README 列明每个渠道每项指标的真实来源、所需权限和已知限制。
